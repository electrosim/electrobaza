# Как добавлять учебные материалы в «Электробазу»

Это руководство описывает полный путь от новой темы до её появления на сайте: создать папки и HTML-страницу, подключить материал в `materials.json`, проверить локально и подготовить изменения к публикации через GitHub Desktop.

## Как устроен каталог

Сайт берёт список групп, дисциплин, тем и материалов из корневого файла `materials.json`. Текст лекции или задания хранится отдельно в HTML-файле внутри `content/`.

```text
materials.json
content/
  groups/
    <идентификатор-группы>/
      <идентификатор-дисциплины>/
        [semester-<номер>/]
          <идентификатор-темы>/
            <идентификатор-материала>.html
```

Сначала идёт группа, затем дисциплина. Если для одной дисциплины в разных группах разные семестры или варианты курса, каждый вариант хранится отдельно. Например:

```text
content/groups/1eo-25/mdk-04-02/semester-1/
content/groups/1eo-24/mdk-04-02/semester-3/
```

Идентификаторы в путях должны совпадать с `id` записей каталога. Пишите их латиницей, строчными буквами и через дефис: `ohms-law`, `series-circuit`, `mdk-04-02-1eo-24-s3`. Не используйте пробелы, `/`, обратную косую черту и русские буквы в идентификаторах. Видимые студентам названия при этом пишутся по-русски.

## Что вносится в какой файл

- HTML-файл содержит только учебный материал: текст, заголовки, списки, таблицы и изображения.
- `materials.json` связывает группу с дисциплиной, дисциплину с темой, а тему — с материалами.
- `catalogue-data.js` — создаваемый файл для локальной работы сайта. Обычно вручную его не редактируют: его обновляет `build-catalogue.cmd`.

Чтобы материал появился на сайте, нужны и HTML-файл, и записи в `materials.json`. Одного HTML-файла недостаточно: сайт не сканирует папки автоматически.

## Пошагово: добавить новую тему и материалы

### 1. Найдите нужную дисциплину и её папку

Откройте `materials.json` и найдите дисциплину в массиве `disciplines`. Проверьте группу, название, `contentPath` и, если указан, семестр. Не ориентируйтесь только на одинаковое название дисциплины: например, МДК 04.02 в разных группах и семестрах — это разные варианты курса.

Для группы 1ЭО-24 и третьего семестра путь начинается так:

```text
content/groups/1eo-24/mdk-04-02/semester-3/
```

Для новой темы придумайте короткий идентификатор, например `ohms-law`. Создайте папку темы внутри папки дисциплины:

```text
content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/
```

Если папки группы или дисциплины уже существуют, используйте существующие — не создавайте копии с немного отличающимися названиями.

### 2. Создайте HTML-файлы материалов

Для каждого отдельного материала создайте файл с понятным именем: `Лекция.html`, `Практическая работа.html`, `Лабораторная работа.html` или, если в этой теме несколько лекций, например, `Лекция 1.html`. Имя файла и значение `id` материала в каталоге должны быть понятными и уникальными.

Файлы можно называть по-русски, в том числе с пробелами: сайт берёт путь из поля `file` и кодирует его автоматически, поэтому такие имена работают и локально, и на GitHub Pages. Папки (`groups`, `mdk-04-02`, `semester-3`, папка темы) и `id` материалов при этом остаются латиницей.

Файлы сайта являются HTML-фрагментами, которые вставляются внутрь готовой страницы. Поэтому **не добавляйте** в них `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`, `<style>` или `<script>`. Не задавайте оформление шрифтов и ширины страницы: сайт уже обеспечивает крупный текст и адаптацию к экрану телефона.

Можно использовать:

- `<section>` для логического раздела;
- `<h2>` для заголовка раздела, `<h3>` для подраздела;
- `<p>`, `<ul>`, `<ol>`, `<li>` для текста и списков;
- `<strong>` и `<em>` для смыслового выделения;
- `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` для таблиц;
- `<figure>`, `<img>`, `<figcaption>` для иллюстраций.

Не начинайте страницу с повторения названия занятия крупным заголовком: название темы и тип материала сайт уже показывает над текстом. Начинайте с первого содержательного раздела, например «Цель занятия» или «Основное понятие».

### 3. Подключите тему в `materials.json`

В записи нужной дисциплины добавьте тему в массив `topics`. Пример фрагмента:

```json
{
  "id": "mdk-04-02-1eo-24-s3",
  "name": "МДК 04.02 Организация работ по сборке, монтажу и ремонту электрооборудования",
  "semester": 3,
  "contentPath": "groups/1eo-24/mdk-04-02/semester-3",
  "topics": [
    {
      "id": "ohms-law",
      "name": "Закон Ома для участка цепи",
      "materials": [
        "ohms-law-lecture",
        "ohms-law-practice"
      ]
    }
  ]
}
```

Если у дисциплины уже есть темы, не заменяйте весь массив: добавьте новый объект в конец или в нужное место. Порядок тем в массиве — порядок отображения для студентов.

### 4. Добавьте записи материалов

В корневом массиве `materials` добавьте запись для каждого HTML-файла. Значение `id` должно в точности совпадать со значением в массиве `materials` темы. Поле `file` — путь от корня проекта, с прямыми `/`:

```json
{
  "id": "ohms-law-lecture",
  "type": "lecture",
  "name": "Лекция",
  "description": "Закон Ома для участка цепи",
  "file": "content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/Лекция.html"
},
{
  "id": "ohms-law-practice",
  "type": "practice",
  "name": "Практическая работа",
  "description": "Расчёт параметров участка электрической цепи",
  "file": "content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/Практическая работа.html"
}
```

Разрешённые значения `type`: `lecture` (лекция), `practice` (практическая работа), `lab` (лабораторная работа), `slides` (презентация) и `file` (файл). Для учебного текста используйте `lecture`, `practice` или `lab`. Для обычных лекций и заданий не ставьте тип `slides`: для него предусмотрен особый режим показа слайдов.

Поле `description` кратко поясняет материал на карточке, а не заменяет текст самого задания. Оно необязательное, но полезное. Поля `id`, `type`, `name` и `file` должны быть указаны.

### 5. Проверьте JSON и связи

Перед просмотром убедитесь, что:

1. В JSON используются двойные кавычки, а между соседними объектами стоят запятые. После последнего элемента запятую не ставят.
2. `id` темы уникален внутри дисциплины, а каждый `id` материала уникален в общем массиве `materials`.
3. Все ID из списка `materials` темы существуют в корневом массиве `materials`.
4. Каждый путь из `file` ведёт к существующему HTML-файлу.
5. Запись дисциплины находится в `disciplines` нужной группы: её ID включён в список `disciplines` соответствующей группы.
6. Семестр, папка и группа соответствуют друг другу.

Если один и тот же файл действительно подходит нескольким группам, тему и ID материала можно подключить в каталогах обеих дисциплин. Убедитесь, что путь `file` ведёт к одному общему HTML-файлу. Не делайте так для разных семестров, пока содержание не сверено с обеими программами.

## Шаблон лекции

Скопируйте этот фрагмент в файл `Лекция.html` и замените текст на содержание занятия. Оставьте структуру разделов, которые подходят теме; ненужные разделы удалите.

```html
<section>
  <h2>Цель занятия</h2>
  <p>После занятия студент сможет объяснить ... и применить ...</p>
</section>

<section>
  <h2>Ключевые понятия</h2>
  <ul>
    <li><strong>Термин</strong> — краткое и точное определение.</li>
    <li><strong>Величина</strong> — обозначение, смысл и единица измерения.</li>
  </ul>
</section>

<section>
  <h2>Основной материал</h2>
  <p>Объясните идею простыми фразами. Один абзац — одна основная мысль.</p>
  <h3>Первый вопрос</h3>
  <p>Дайте объяснение, затем приведите пример или покажите связь с практикой.</p>
</section>

<section>
  <h2>Пример</h2>
  <ol>
    <li>Запишите исходные данные и переведите величины в нужные единицы.</li>
    <li>Выберите формулу и покажите подстановку чисел.</li>
    <li>Запишите ответ с единицей измерения и проверьте его разумность.</li>
  </ol>
</section>

<section>
  <h2>Краткий вывод</h2>
  <p>Сформулируйте главное, что нужно запомнить.</p>
</section>

<section>
  <h2>Вопросы для самопроверки</h2>
  <ol>
    <li>Как объяснить ...?</li>
    <li>В каких единицах измеряется ...?</li>
    <li>Как применить изученное на практике?</li>
  </ol>
</section>
```

Для формул используйте понятную запись и HTML-индексы `<sub>` и `<sup>`, например `I = U / R`, `U<sub>1</sub>` или `10<sup>3</sup>`. Если формула сложная, добавьте рядом пояснение обозначений словами. Специальная библиотека математической разметки в сайте сейчас не подключена.

## Шаблон практической или лабораторной работы

Скопируйте фрагмент в `Практическая работа.html` или `Лабораторная работа.html`. Для практической работы добавьте исходные данные и задания; для лабораторной — оборудование, порядок наблюдений, таблицу результатов и требования к отчёту.

```html
<section>
  <h2>Цель работы</h2>
  <p>Научиться ... и закрепить умение ...</p>
</section>

<section>
  <h2>Оборудование и материалы</h2>
  <ul>
    <li>укажите нужное оборудование и материалы;</li>
    <li>укажите схему, инструкцию или исходные данные.</li>
  </ul>
</section>

<section>
  <h2>Безопасность</h2>
  <ul>
    <li>Укажите правила для конкретного задания и оборудования.</li>
    <li>Опишите, какие действия выполняются только по разрешению преподавателя.</li>
  </ul>
</section>

<section>
  <h2>Порядок выполнения</h2>
  <ol>
    <li><strong>Подготовьтесь.</strong> Изучите схему, исходные данные и требования.</li>
    <li><strong>Выполните задание.</strong> Записывайте ход работы и результаты.</li>
    <li><strong>Проверьте результат.</strong> Сверьте расчёт или наблюдения с ожидаемыми.</li>
    <li><strong>Сформулируйте вывод.</strong> Ответьте, достигнута ли цель работы.</li>
  </ol>
</section>

<section>
  <h2>Задания</h2>
  <ol>
    <li>Первое задание с конкретными исходными данными.</li>
    <li>Второе задание или дополнительный вариант.</li>
  </ol>
</section>

<section>
  <h2>Что включить в отчёт</h2>
  <ul>
    <li>цель и исходные данные;</li>
    <li>ход работы, расчёты или таблицу результатов;</li>
    <li>ответы на контрольные вопросы и вывод.</li>
  </ul>
</section>

<section>
  <h2>Контрольные вопросы</h2>
  <ol>
    <li>Как объяснить полученный результат?</li>
    <li>Какие данные или измерения подтвердили вывод?</li>
  </ol>
</section>
```

Для электротехнических заданий указывайте именно те модели оборудования, схемы и обозначения, которые предусмотрены учебной работой. Не переносите номера клемм и номиналы с похожего аппарата. Инструкции по работе со стендом и электрической безопасностью должны соответствовать реальному оборудованию и порядку, установленному преподавателем.

## Иллюстрации и таблицы

Создайте папку `images` рядом с HTML-файлами темы и храните изображения там. В `src` указывайте путь от корня проекта, а не только имя файла: он должен работать и при открытии `index.html` локально, и на GitHub Pages.

```text
content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/
  Лекция.html
  Практическая работа.html
  docs/
    Лекция — Закон Ома.docx
  images/
    circuit.png
```

В `Лекция.html` используйте:

```html
<figure>
  <img src="content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/images/circuit.png"
       alt="Схема участка электрической цепи с источником напряжения и резистором">
  <figcaption>Рисунок 1 — Участок цепи для разбора закона Ома</figcaption>
</figure>
```

Всегда пишите содержательное `alt`, чтобы смысл рисунка был понятен, если он не загрузится. Не используйте адреса файлов с вашего компьютера (`D:\...`) и временные ссылки. Таблицы делайте компактными: на узком экране слишком много широких столбцов читать неудобно; единицы указывайте в заголовке столбца.

## Документы занятия

Скачиваемые файлы к конкретному занятию — Word-версии лекций, задания, бланки отчётов — храните в папке `docs` внутри папки этой же темы. Не складывайте документы разных занятий в общую папку: тогда файлы легко найти, а удаление темы удаляет и её документы.

```text
content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/
  Лекция.html
  Практическая работа.html
  docs/
    Лекция — Закон Ома.docx
  images/
    circuit.png
```

Ссылку на документ давайте от корня проекта, как и изображения:

```html
<p><a href="content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/docs/Лекция — Закон Ома.docx">Скачать лекцию в Word (.docx)</a></p>
```

Пробелы и русские буквы в пути браузер кодирует сам, но адрес не должен содержать `..` и букв диска. Word-документ дублирует HTML-материал: если исправляете текст, обновите оба файла и заново запустите `build-catalogue.cmd`.

## Локальная проверка

1. Сохраните HTML-файлы и `materials.json`.
2. Запустите `build-catalogue.cmd`. Он проверит, что JSON читается, найдёт все указанные HTML-файлы и обновит `catalogue-data.js`.
3. Откройте или обновите `index.html` и пройдите путь: группа → дисциплина → тема → материал.
4. Проверьте чтение в мобильной ширине: заголовки не должны повторяться, изображения должны помещаться по ширине, таблицы и списки должны оставаться понятными.
5. Исправьте ошибки, снова запустите сборку и обновите страницу.

Для предпросмотра, который сам пересобирает каталог после сохранения изменений, используйте `preview.cmd` и оставьте открытое окно предпросмотра запущенным. Для простого двойного щелчка по `index.html` после изменения `materials.json` или HTML тоже сначала выполните `build-catalogue.cmd`.

Если сборка сообщает об ошибке JSON, сначала проверьте запятые и кавычки. Если она не находит файл, сверьте поле `file` с фактическим путём и написанием имени. Если страница показывает «Материал пока недоступен», проверьте, что ID материала в теме совпадает с ID записи в корневом массиве `materials`.

## Публикация через GitHub Desktop

После локальной проверки:

1. Откройте репозиторий «Электробаза» в GitHub Desktop.
2. Просмотрите список изменений. В коммит должны попасть HTML-файлы, `materials.json` и обновлённый `catalogue-data.js`.
3. Убедитесь, что новые изображения также добавлены, если они используются.
4. Создайте понятный коммит, например `Добавлена тема: Закон Ома`.
5. Отправьте коммит в репозиторий и дождитесь публикации GitHub Pages.
6. Откройте опубликованный сайт и проверьте тот же путь до материала.

Если материал содержит только общедоступный учебный текст, он будет доступен любому, у кого есть ссылка на сайт. Не добавляйте персональные данные студентов, закрытые документы или материалы, которые нельзя публиковать.

- [ ] Создана папка темы внутри папки этой дисциплины.
- [ ] HTML — фрагмент без `<html>`, `<head>`, `<body>`, `<style>` и `<script>`.
- [ ] В теме перечислены ID материалов, а записи этих материалов есть в `materials.json`.
- [ ] Все пути `file` указывают на существующие HTML-файлы.
- [ ] Изображения имеют корректные пути от корня проекта и заполненный `alt`.
- [ ] `build-catalogue.cmd` завершился без ошибок.
- [ ] Материал проверен локально и на мобильной ширине.
- [ ] В GitHub Desktop подготовлены все изменённые и новые файлы.
