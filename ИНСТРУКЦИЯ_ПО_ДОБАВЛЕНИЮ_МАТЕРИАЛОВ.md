# Инструкция и правила добавления материалов в «Электробазу»

Это единый документ: в первой части собраны правила содержания, объёма и оформления материалов, во второй — пошаговая техническая инструкция: папки, HTML, `materials.json`, проверка и публикация.

Перед созданием каждой новой лекции обязательно задаются уточняющие вопросы по анкете из раздела 1: объём, тема, расчёты, графики, таблицы, иллюстрации, Word/HTML и оформление. Прежние ответы не подставляются по памяти.

## Часть I. Правила

### 1. Обязательная анкета перед каждой лекцией

Перед тем как писать новую лекцию или переделывать существующую, задать пользователю уточняющие вопросы. Не начинать работу, пока не получены ответы хотя бы по объёму, теме и необходимости расчётов и графиков. Прежние ответы не подставлять по памяти.

Стандартный набор вопросов:

1. **Объём.** Сколько страниц A4 нужно: 1, 1,5, 2 или другой объём? Нужен ли жёсткий лимит?
2. **Тема и границы.** О чём именно лекция, что входит в тему, а что не нужно? Есть ли готовое название?
3. **Аудитория.** Для какой группы, дисциплины и семестра материал? Это влияет на уровень и примеры. **Эти данные нужны только для выбора уровня: в сам документ лекции их не выносить.**
4. **Содержание.** Какие разделы обязательны, какие можно опустить? Нужны ли определения, классификация, применение, порядок расчёта, выводы?
5. **Расчёты.** Нужны ли формулы и числовые примеры? Сколько примеров, какой вариант брать за основу? Нужны ли варианты заданий?
6. **Графики.** Нужны ли графики, сколько и какие зависимости показывать? Строить схемы/графики в SVG или вставлять готовые изображения?
7. **Таблицы.** Нужны ли таблицы, какие данные в них, сколько столбцов?
8. **Иллюстрации.** Нужны ли фотографии и схемы? Брать из интернета, из папки темы или ждать файлы от пользователя? Можно ли указывать источники?
9. **Формат.** Нужны обе версии — Word и HTML, или только одна? Word нужен для печати или для скачивания с сайта?
10. **Оформление.** По умолчанию используется стандартное оформление без служебного подзаголовка, без названия группы и дисциплины; отдельно этот вопрос больше не задавать. Спрашивать только если пользователь сам предложит особое оформление.
11. **Замена.** Новая лекция заменяет существующую или добавляется рядом? Что делать со старой версией?
12. **Источники и права.** Откуда брать изображения, есть ли ограничения по лицензиям и атрибуции?
13. **Сроки и проверка.** Нужна ли проверка на мобильной ширине, нужен ли PDF, есть ли дедлайн?

Если пользователь ответил не на все пункты, задать недостающие вопросы одним сообщением. Не додумывать объём, число графиков, наличие расчётов и источники изображений.

### 2. Практические работы

- Если оборудования нет, работа делается **только расчётной**: без стенда, монтажа, наладки, измерений, поиска неисправностей, оборудования и раздела безопасности.
- В расчётной работе должны быть: цель, исходные данные, варианты, формулы, пример расчёта, таблицы, графики, отчёт и контрольные вопросы.
- Объём не раздувать. Для работы 1ЭО-24 по теме расцепителя и датчика ориентир — около 8–9 КБ HTML, примерно в 3 раза меньше первоначального варианта.
- Число вариантов и номер примера отдельно не задавались: принято 8 вариантов и пример по варианту 8. Для новой работы эти числа уточнять.
- В тексте не должно быть упоминаний реального оборудования, если работа расчётная.
- **Каждая практическая работа существует в двух версиях:** HTML для сайта и Word для печати. Word-файл хранится в `docs` темы, а в HTML-версии добавляется ссылка «Скачать работу в Word (.docx)».
- Word-версия практической повторяет структуру HTML: цель, исходные данные, таблицы, формулы, графики, отчёт, контрольные вопросы. Оформление — по разделу 4.

### 3. Лекции

- Лекция должна быть простой и посвящённой заявленной теме, без лишних разделов.
- **Не вписывать в документ лекции группу, дисциплину, семестр, номер пары и подобные служебные данные** — ни в заголовок, ни в подзаголовок, ни в колонтитул, ни в первый абзац. Эти данные уже есть в каталоге сайта и в пути к папке.
- **Не писать подзаголовок** «Краткая лекция · МДК 04.02, 3-й семестр» и подобные служебные подзаголовки. Документ начинается с названия темы.
- Каждая лекция существует в двух версиях:
  - HTML-фрагмент для сайта;
  - Word-документ для печати и скачивания.
- HTML-версию обязательно добавлять в `materials.json` как материал типа `lecture` в ту же тему, а не просто класть файл в папку.
- Word-файл хранить в папке `docs` этой темы; HTML — в корне папки темы; изображения — в `images`.
- В конце HTML-лекции можно давать ссылку на практическую работу и на скачивание Word-файла.

### 4. Оформление Word-материалов

Правила этого раздела относятся и к лекциям, и к практическим работам.

- A4, поля 2 см, Times New Roman 11 pt, межстрочный интервал 1,1–1,15.
- Заголовки — стилем `Heading 1`, основной текст — с абзацным отступом и выравниванием по ширине.
- Каждая формула — отдельным абзацем по центру.
- Подписи к рисункам: «Рисунок N — Название.». Без строк «Фото: …», «Источник: …» и без ссылок.
- Если несколько рисунков подряд, следить, чтобы документ не разрастался: уменьшать ширину фото (около 3,8–4,2 см), а не только текст.
- После сборки проверять фактическое число страниц в LibreOffice/Word, а не только размер файла.

### 5. Формулы

- Каждая формула — с новой строки. Не объединять несколько формул в одну строку через точку с запятой.
- Для формул использовать `<ul class="formulas">` и отдельные `<li>`.
- Если формула не помещается по ширине, уменьшать её кегль классом `small`, а не переносить на вторую строку.
- Проверять, что в HTML не остались напечатанные `SUB`/`SUP` и `&lt;sub&gt;`: индексы должны быть настоящими тегами `<sub>`/`<sup>`.
- В Word индексы делать через `run.font.subscript`/`superscript`, а не текстом.

### 6. Таблицы

- Таблицы компактные: 3–4 столбца, единицы измерения в заголовках.
- Заголовок таблицы — через `<caption>`.
- На мобильной ширине таблица должна помещаться по ширине; при необходимости уменьшать шрифт в медиазапросе.
- Не делать широкие таблицы на 6–7 столбцов без необходимости.

### 7. Изображения

- Разрешено брать картинки из интернета, если они подходят по смыслу и лицензии.
- Изображения хранить в `images` темы, в HTML указывать путь от корня сайта, обязательно заполнять `alt`.
- **Не указывать ссылки на изображения** и не писать в подписях «Фото: …», «Wikimedia Commons», «Источник: …». Подпись — только номер и название. При этом локальный `src` к файлу в `images` обязателен: без него картинка не отобразится.
- Если лицензия изображения требует атрибуции (например, CC BY-SA), а подписи со ссылками запрещены, использовать собственные или CC0-изображения либо отдельно согласовать с преподавателем, где указать атрибуцию.
- Пользовательские изображения добавлять по прямой просьбе; происхождение и права на них уточнять у пользователя.

### 8. Файлы и папки

- Имена HTML- и Word-файлов — **по-русски**, можно с пробелами: `Лекция (расцепитель).html`, `Практическая работа.html`, `Лекция — Расцепитель минимального напряжения.docx`.
- Папки и `id` материалов — **латиницей**: `1eo-24`, `mdk-04-02`, `semester-3`, `undervoltage-release-light-sensor`.
- Документы занятия — в папке `docs` внутри папки темы, а не в общей корневой `docs`.
- Python-генераторы Word/HTML не обязательны: сайт и готовые документы от них не зависят. Если генератор используется, хранить его вне папки занятия, например в `tools/`, и не добавлять в `docs` темы.
- При переименовании файлов обновлять:
  - `materials.json` (`file`);
  - ссылку на Word в HTML-лекции;
  - пути к изображениям;
  - `catalogue-data.js` пересборкой.

### 9. Проверка перед сдачей

1. `build-catalogue.cmd` (или `node build-catalogue.mjs`) проходит без ошибок.
2. `materials.json` — валидный JSON; все `file` существуют; все ID из тем есть в массиве `materials`.
3. HTML-фрагмент корректный, без `<!DOCTYPE>`, `<html>`, `<head>`, `<body>`, `<style>`, `<script>`.
4. Все изображения открываются; внешних ссылок в подписях нет.
5. Формулы отображаются с индексами, без `SUB`.
6. Word открывается, число страниц соответствует согласованному объёму.
7. Страница проверена в браузере на мобильной ширине (около 390 px).

## Часть II. Инструкция

### Как устроен каталог

Сайт берёт список групп, дисциплин, тем и материалов из корневого файла `materials.json`. Текст лекции или задания хранится отдельно в HTML-файле внутри `content/`.

```text
materials.json
content/
  groups/
    <идентификатор-группы>/
      <идентификатор-дисциплины>/
        [semester-<номер>/]
          <идентификатор-темы>/
            <идентификатор-материала>.html
```

Сначала идёт группа, затем дисциплина. Если для одной дисциплины в разных группах разные семестры или варианты курса, каждый вариант хранится отдельно. Например:

```text
content/groups/1eo-25/mdk-04-02/semester-1/
content/groups/1eo-24/mdk-04-02/semester-3/
```

Идентификаторы в путях должны совпадать с `id` записей каталога. Пишите их латиницей, строчными буквами и через дефис: `ohms-law`, `series-circuit`, `mdk-04-02-1eo-24-s3`. Не используйте пробелы, `/`, обратную косую черту и русские буквы в идентификаторах. Видимые студентам названия при этом пишутся по-русски.

### Что вносится в какой файл

- HTML-файл содержит только учебный материал: текст, заголовки, списки, таблицы и изображения.
- `materials.json` связывает группу с дисциплиной, дисциплину с темой, а тему — с материалами.
- `catalogue-data.js` — создаваемый файл для локальной работы сайта. Обычно вручную его не редактируют: его обновляет `build-catalogue.cmd`.

Чтобы материал появился на сайте, нужны и HTML-файл, и записи в `materials.json`. Одного HTML-файла недостаточно: сайт не сканирует папки автоматически.

### Пошагово: добавить новую тему и материалы

#### 1. Найдите нужную дисциплину и её папку

Откройте `materials.json` и найдите дисциплину в массиве `disciplines`. Проверьте группу, название, `contentPath` и, если указан, семестр. Не ориентируйтесь только на одинаковое название дисциплины: например, МДК 04.02 в разных группах и семестрах — это разные варианты курса.

Для группы 1ЭО-24 и третьего семестра путь начинается так:

```text
content/groups/1eo-24/mdk-04-02/semester-3/
```

Для новой темы придумайте короткий идентификатор, например `ohms-law`. Создайте папку темы внутри папки дисциплины:

```text
content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/
```

Если папки группы или дисциплины уже существуют, используйте существующие — не создавайте копии с немного отличающимися названиями.

#### 2. Создайте HTML-файлы материалов

Для каждого отдельного материала создайте файл с понятным именем: `Лекция.html`, `Практическая работа.html`, `Лабораторная работа.html` или, если в этой теме несколько лекций, например, `Лекция 1.html`. Имя файла и значение `id` материала в каталоге должны быть понятными и уникальными.

Файлы можно называть по-русски, в том числе с пробелами: сайт берёт путь из поля `file` и кодирует его автоматически, поэтому такие имена работают и локально, и на GitHub Pages. Папки (`groups`, `mdk-04-02`, `semester-3`, папка темы) и `id` материалов при этом остаются латиницей.

Файлы сайта являются HTML-фрагментами, которые вставляются внутрь готовой страницы. Поэтому **не добавляйте** в них `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`, `<style>` или `<script>`. Не задавайте оформление шрифтов и ширины страницы: сайт уже обеспечивает крупный текст и адаптацию к экрану телефона.

Можно использовать:

- `<section>` для логического раздела;
- `<h2>` для заголовка раздела, `<h3>` для подраздела;
- `<p>`, `<ul>`, `<ol>`, `<li>` для текста и списков;
- `<strong>` и `<em>` для смыслового выделения;
- `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` для таблиц;
- `<figure>`, `<img>`, `<figcaption>` для иллюстраций.

Не начинайте страницу с повторения названия занятия крупным заголовком: название темы и тип материала сайт уже показывает над текстом. Начинайте с первого содержательного раздела, например «Цель занятия» или «Основное понятие».

#### 3. Подключите тему в `materials.json`

В записи нужной дисциплины добавьте тему в массив `topics`. Пример фрагмента:

```json
{
  "id": "mdk-04-02-1eo-24-s3",
  "name": "МДК 04.02 Организация работ по сборке, монтажу и ремонту электрооборудования",
  "semester": 3,
  "contentPath": "groups/1eo-24/mdk-04-02/semester-3",
  "topics": [
    {
      "id": "ohms-law",
      "name": "Закон Ома для участка цепи",
      "materials": [
        "ohms-law-lecture",
        "ohms-law-practice"
      ]
    }
  ]
}
```

Если у дисциплины уже есть темы, не заменяйте весь массив: добавьте новый объект в конец или в нужное место. Порядок тем в массиве — порядок отображения для студентов.

#### 4. Добавьте записи материалов

В корневом массиве `materials` добавьте запись для каждого HTML-файла. Значение `id` должно в точности совпадать со значением в массиве `materials` темы. Поле `file` — путь от корня проекта, с прямыми `/`:

```json
{
  "id": "ohms-law-lecture",
  "type": "lecture",
  "name": "Лекция",
  "description": "Закон Ома для участка цепи",
  "file": "content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/Лекция.html"
},
{
  "id": "ohms-law-practice",
  "type": "practice",
  "name": "Практическая работа",
  "description": "Расчёт параметров участка электрической цепи",
  "file": "content/groups/1eo-24/mdk-04-02/semester-3/ohms-law/Практическая работа.html"
}
```

Разрешённые значения `type`: `lecture` (лекция), `practice` (практическая работа), `lab` (лабораторная работа), `slides` (презентация) и `file` (файл). Для учебного текста используйте `lecture`, `practice` или `lab`. Для обычных лекций и заданий не ставьте тип `slides`: для него предусмотрен особый режим показа слайдов.

Поле `description` кратко поясняет материал на карточке, а не заменяет текст самого задания. Оно необязательное, но полезное. Поля `id`, `type`, `name` и `file` должны быть указаны.

#### 5. Проверьте JSON и связи

Перед просмотром убедитесь, что:

1. В JSON используются двойные кавычки, а между соседними объектами стоят запятые. После последнего элемента запятую не ставят.
2. `id` темы уникален внутри дисциплины, а каждый `id` материала уникален в общем массиве `materials`.
3. Все ID из списка `materials` темы существуют в корневом массиве `materials`.
4. Каждый путь из `file` ведёт к существующему HTML-файлу.
5. Запись дисциплины находится в `disciplines` нужной группы: её ID включён в список `disciplines` соответствующей группы.
6. Семестр, папка и группа соответствуют друг другу.

Если один и тот же файл действительно подходит нескольким группам, тему и ID материала можно подключить в каталогах обеих дисциплин. Убедитесь, что путь `file` ведёт к одному общему HTML-файлу. Не делайте так для разных семестров, пока содержание не сверено с обеими программами.

### Шаблон лекции

Перед созданием лекции задайте уточняющие вопросы по анкете из [«Обязательной анкеты перед каждой лекцией»](#1-обязательная-анкета-перед-каждой-лекцией): объём в страницах A4, содержание, необходимость расчётов, графиков и таблиц, иллюстрации, формат Word/HTML. Объём задаётся для каждой лекции отдельно и не переносится из предыдущей.

Скопируйте этот фрагмент в файл `Лекция.html` и замените текст на содержание занятия. Оставьте структуру разделов, которые подходят теме; ненужные разделы удалите.

```html
<section>
  <h2>Цель занятия</h2>
  <p>После занятия студент сможет объяснить ... и применить ...</p>
</section>

<section>
  <h2>Ключевые понятия</h2>
  <ul>
    <li><strong>Термин</strong> — краткое и точное определение.</li>
    <li><strong>Величина</strong> — обозначение, смысл и единица измерения.</li>
  </ul>
</section>

<section>
  <h2>Основной материал</h2>
  <p>Объясните идею простыми фразами. Один абзац — одна основная мысль.</p>
  <h3>Первый вопрос</h3>
```

### Локальная проверка

1. Сохраните HTML-файлы и `materials.json`.
2. Запустите `build-catalogue.cmd`. Он проверит, что JSON читается, найдёт все указанные HTML-файлы и обновит `catalogue-data.js`.
3. Откройте или обновите `index.html` и пройдите путь: группа → дисциплина → тема → материал.
4. Проверьте чтение в мобильной ширине: заголовки не должны повторяться, изображения должны помещаться по ширине, таблицы и списки должны оставаться понятными.
5. Исправьте ошибки, снова запустите сборку и обновите страницу.

Для предпросмотра, который сам пересобирает каталог после сохранения изменений, используйте `preview.cmd` и оставьте открытое окно предпросмотра запущенным. Для простого двойного щелчка по `index.html` после изменения `materials.json` или HTML тоже сначала выполните `build-catalogue.cmd`.

Если сборка сообщает об ошибке JSON, сначала проверьте запятые и кавычки. Если она не находит файл, сверьте поле `file` с фактическим путём и написанием имени. Если страница показывает «Материал пока недоступен», проверьте, что ID материала в теме совпадает с ID записи в корневом массиве `materials`.

### Публикация через GitHub Desktop

После локальной проверки:

1. Откройте репозиторий «Электробаза» в GitHub Desktop.
2. Просмотрите список изменений. В коммит должны попасть HTML-файлы, `materials.json` и обновлённый `catalogue-data.js`.
3. Убедитесь, что новые изображения также добавлены, если они используются.
4. Создайте понятный коммит, например `Добавлена тема: Закон Ома`.
5. Отправьте коммит в репозиторий и дождитесь публикации GitHub Pages.
6. Откройте опубликованный сайт и проверьте тот же путь до материала.

Если материал содержит только общедоступный учебный текст, он будет доступен любому, у кого есть ссылка на сайт. Не добавляйте персональные данные студентов, закрытые документы или материалы, которые нельзя публиковать.
